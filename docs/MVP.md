# MVP

## Цель

Примерно за пять часов реализации показать полный и надёжный сценарий прогресса без ручного редактирования базы данных и перезагрузки страницы.

## Обязательная функциональность

- Показать выбранного из трёх подготовленных Игроков: имя, XP, уровень, титул и состояние персонажа.
- Показать Квесты в колонках `TODO`, `IN_PROGRESS` и `DONE`.
- Показать активный командный рейд с оставшимся HP босса или понятное отсутствие активного Raid.
- Завершить один Квест через детерминированный демонстрационный endpoint/действие.
- Начислить XP Квеста ровно один раз.
- В той же бэкенд-операции рассчитать новый уровень и одну косметическую награду.
- Нанести урон рейду тем же завершением.
- Без перезагрузки обновить Квест, шкалу XP, реакцию персонажа, награду и состояние босса.

## Обязательные понятия

- `Player`: идентификатор, общий XP, уровень, текущая косметика/титул.
- `Quest`: название, статус, награда XP, исполнитель, необязательная внешняя ссылка.
- `Raid`: название, описание, максимальный и текущий HP, lifecycle-статус и необязательная внешняя ссылка.
- `ProgressionResult`: результат завершения Квеста.

Точная модель хранения и API согласуется на Этапе 0; см. [backend/README.md](backend/README.md) и [ARCHITECTURE.md](ARCHITECTURE.md).

## Основной пользовательский сценарий

1. Dashboard и доска загружают текущее демонстрационное состояние из Spring Boot.
2. Событие завершения указывает незавершённый Квест.
3. Одна транзакция бэкенда завершает Квест, начисляет XP, рассчитывает уровень/награду и наносит урон активному Raid, если он есть.
4. Фронтенд получает полный результат в ответе команды и/или realtime-событии.
5. Интерфейс последовательно показывает завершение Квеста, XP, реакцию персонажа, новый уровень/награду и урон боссу.

## Критерий готовности MVP

Полный сценарий многократно запускается из известного подготовленного состояния, безопасно обрабатывает повторное завершение и проходит проверки из [DEMO.md](DEMO.md). Он работает без GitHub, n8n, CI и внешнего AI.

## Что явно не входит в MVP

- Аутентификация и мультитенантность.
- Полная установка GitHub App и широкий набор webhook-событий.
- Сложные инвентарь, экипировка, достижения или дерево прогресса.
- Расширение браузера, социальная публикация и AI-оценка XP.
- Drag-and-drop редактирование доски или полноценный менеджер проектов.
- Промышленная событийная инфраструктура или микросервисы.

## Что разрешено симулировать

- Трёх подготовленных игроков, небольшой распределённый набор Квестов, один рейд и один порог награды.
- Явно обозначенный демонстрационный триггер, вызывающий тот же сервис, что и будущий GitHub-адаптер.
- Polling или обновление из ответа команды, если WebSocket угрожает пятичасовому сроку.
- Временные изображения персонажа до получения прозрачных PNG-кадров.

## Решения Этапа 0.1

- Используется общий XP с фиксированными порогами и сохранением остатка.
- Урон рейду равен фактически начисленному XP.
- REST-ответ обязателен; WebSocket остаётся необязательным дополнением после короткой проверки.

Точные payload, значения и ошибки: [stages/00-contracts/README.md](stages/00-contracts/README.md).
