# Фронтенд

## Текущее состояние

Фронтенд — Vue 3 + TypeScript + Quasar Dashboard со светлой игровой темой. Реализованы layout, карточки игрока/Квеста/рейда, CRUD-доска, drawer завершения, toast, адаптивность, строгие API-типы, Axios instance, Pinia store и STOMP-клиент.

Dashboard, Quests и Raids используют общий серверный state. REST-ответ применяется сразу, а realtime синхронизирует завершение Квестов без повторной реакции одного `eventId`.

## Основные страницы

- `/` Dashboard: главная сцена и живой серверный сценарий.
- `/quests`: серверные Квесты в пяти колонках, создание, редактирование, удаление, перемещение и завершение через backend.
- `/raids`: управление lifecycle Raid с Active, Draft и History, созданием, редактированием и явными командами.
- Achievements остаётся декоративным пунктом без маршрута.

Настройки доски изменяют только представление: порядок, названия и видимость колонок, компактный режим и показ завершённых Квестов. Они сохраняются локально; сами Квесты всегда берутся с backend.

## Группы компонентов

- `dashboard`: игрок, активный Квест, активность, панель рейда/босса.
- `quests`: доска, колонка, карточка, необязательный dialog/drawer деталей.
- `character`: отображение кадров, XP/уровень, косметика и награда.
- `progression`: сообщение о завершении и последовательность анимаций.
- `shared`: компактные loading/error состояния и игровые оболочки карточек.

Не строить отдельную дизайн-систему в рамках хакатона.

## Состояние и поток данных

Текущий поток данных:

1. API-модуль загружает `DemoState` из backend.
2. Store хранит серверные снимки отдельно от настроек представления.
3. CRUD и move заменяют state полным ответом backend; при ошибке предыдущий state сохраняется.
4. Ответ завершения сразу применяется как `ProgressionResult`.
5. Realtime использует тот же тип и не должен второй раз применять уже обработанный `eventId`.
6. После ошибки или восстановления соединения выполняется полное чтение состояния.

Raid CRUD использует отдельный `/api/raids`. После мутации store перечитывает список Raid и агрегированное demo state, поэтому Dashboard всегда показывает только `ACTIVE`. Progression realtime обновляет затронутый Raid; nullable `raid` означает, что активного босса нет.

Dashboard, layout, Quests, Raids и realtime делят небольшой Pinia store. `useDashboardDemo` отвечает за presentation-состояние и временные реакции; presentation-тексты и timing анимаций в store не помещаются.

## API-слой

- Сохранить существующий Axios instance.
- `src/api/demo.ts` содержит функции state, create, update, delete, move, complete и reset.
- Типизированные функции и DTO держать вне Vue-компонентов.
- Не дублировать расчёты бэкенда и не разбрасывать HTTP-вызовы по компонентам.
- Повторные/устаревшие события применять идемпотентно по финальным данным сервера или id события.
- Fixture вкладок хранят только presentation-данные, но не рабочие снимки доменных объектов.

## Состояние персонажа

Постоянные значения backend: `idle`, `coding`; временные реакции результата: `happy`, `level-up`. В репозитории есть PNG-ассеты, но текущий Dashboard передаёт `characterSrc=null` и показывает placeholder. Подключение кадров — отдельная визуальная правка, не часть API-интеграции.

## Realtime

`src/boot/realtime.ts` запускает единственный клиент при старте приложения. `src/realtime/progression.ts` подключается к `/ws`, подписывается на `/topic/progression` и передаёт типизированный `ProgressionResponse` подписчикам. Для локальной разработки адрес по умолчанию — `ws://localhost:8080/ws`; переопределение задаётся в `VITE_WS_URL`.

Store подписывается через `progressionRealtime.subscribe(handler)` и освобождает подписку при завершении жизненного цикла Dashboard. Инициирующий экран сначала применяет REST-ответ; realtime синхронизирует другие события. После повторного подключения store перечитывает полный state.

## Разделение области

MVP:

- Dashboard, минимальная доска, живые XP/уровень, персонаж, босс и последовательность завершения.
- Достаточная адаптация под экран презентации.

Полировка после MVP:

- История рейдов, Профиль, переходы и журнал активности.

Дополнительные возможности:

- Больше косметики, достижения, sharing и интерфейс браузерного компаньона.

## Вероятное владение

- `src/pages`, `src/components/dashboard`, `src/components/progression`: владелец основного UI.
- `src/api` и общие DTO-типы: владелец контрактов совместно с бэкендом.
- `src/css`, layout, router и точка входа Pinia: общие конфликтные области, редактировать последовательно.
