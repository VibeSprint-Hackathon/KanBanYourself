# Фронтенд

## Текущее состояние

Фронтенд — Vue 3 + TypeScript + Quasar Dashboard со светлой игровой темой. Реализованы layout, карточки игрока/Квеста/рейда, drawer завершения, toast, адаптивность, строгие API-типы, Axios instance и STOMP-клиент. Pinia установлена, но не используется.

Dashboard пока работает на `dashboard.fixture.ts`: начальное состояние и результат Complete Quest являются mock-данными. HTTP-функций для демо API ещё нет, realtime-события не применяются к состоянию страницы. Следующий шаг — I1 из [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md).

## Основные страницы

- `/` Dashboard: единственный реализованный маршрут и главная сцена демонстрации.
- Квесты, рейды и достижения видны в sidebar, но пока не имеют маршрутов.
- После I1 нужна минимальная доска `TODO`/`IN_PROGRESS`/`DONE`; её можно встроить в Dashboard. Отдельные маршруты относятся к полировке.

При нехватке времени Dashboard может включить основную доску и сводку персонажа; отдельные маршруты — удобство после MVP.

## Группы компонентов

- `dashboard`: игрок, активный Квест, активность, панель рейда/босса.
- `quests`: доска, колонка, карточка, необязательный dialog/drawer деталей.
- `character`: отображение кадров, XP/уровень, косметика и награда.
- `progression`: сообщение о завершении и последовательность анимаций.
- `shared`: компактные loading/error состояния и игровые оболочки карточек.

Не строить отдельную дизайн-систему в рамках хакатона.

## Состояние и поток данных

Целевой поток I1:

1. API-модуль загружает `DemoState` из backend.
2. Store хранит серверные снимки отдельно от presentation-данных.
3. Ответ завершения сразу применяется как `ProgressionResult`.
4. Realtime использует тот же тип и не должен второй раз применять уже обработанный `eventId`.
5. После ошибки или восстановления соединения выполняется полное чтение состояния.

Сейчас состояние локально внутри `useDashboardDemo`, а layout отдельно читает имя игрока из fixture. В I1 Dashboard, layout и realtime начинают делить серверное состояние, поэтому один небольшой Pinia store становится оправданным. В store не помещаются presentation-тексты и timing анимаций.

## API-слой

- Сохранить существующий Axios instance.
- Добавить отдельный `src/api/demo.ts` с функциями state, complete и reset.
- Типизированные функции и DTO держать вне Vue-компонентов.
- Не дублировать расчёты бэкенда и не разбрасывать HTTP-вызовы по компонентам.
- Повторные/устаревшие события применять идемпотентно по финальным данным сервера или id события.
- `dashboard.fixture.ts` после I1 хранит только описания, проценты макета и временные визуальные подписи.

## Состояние персонажа

Постоянные значения backend: `idle`, `coding`; временные реакции результата: `happy`, `level-up`. В репозитории есть PNG-ассеты, но текущий Dashboard передаёт `characterSrc=null` и показывает placeholder. Подключение кадров — отдельная визуальная правка, не часть API-интеграции.

## Realtime

`src/boot/realtime.ts` запускает единственный клиент при старте приложения. `src/realtime/progression.ts` подключается к `/ws`, подписывается на `/topic/progression` и передаёт типизированный `ProgressionResponse` подписчикам. Для локальной разработки адрес по умолчанию — `ws://localhost:8080/ws`; переопределение задаётся в `VITE_WS_URL`.

Сейчас boot-клиент соединяется и получает сообщения, но Dashboard на них не подписан. В I1 store подписывается через `progressionRealtime.subscribe(handler)` и освобождает подписку при завершении своего жизненного цикла. Инициирующий экран сначала применяет REST-ответ; realtime синхронизирует другие события.

## Разделение области

MVP:

- Dashboard, минимальная доска, живые XP/уровень, персонаж, босс и последовательность завершения.
- Достаточная адаптация под экран презентации.

Полировка после MVP:

- Отдельные маршруты Квестов/Профиля, переходы и журнал активности.

Дополнительные возможности:

- Больше косметики, достижения, sharing и интерфейс браузерного компаньона.

- `src/pages`, `src/components/dashboard`, `src/components/progression`: владелец основного UI.
- `src/api` и общие DTO-типы: владелец контрактов совместно с бэкендом.
- `src/css`, layout, router и точка входа Pinia: общие конфликтные области, редактировать последовательно.
